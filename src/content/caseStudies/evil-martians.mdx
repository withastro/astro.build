By late 2023, it was clear that Gatsby was winding down, but for three years running, Evil Martians couldn't justify a migration. For a busy consultancy, this meant pulling engineers off client projects indefinitely, a costly and labourous prospect. But to the team's surprise, in August 2026, a single engineer moved the entire website to Astro in just eight days.

On day eight, without changing any React components, and by making every route a whole-page island, the homepage went from 2.1 MB to 1.8 MB. After fully converting to Island architecture, it's 1.1 MB. Homepage JavaScript at load fell 61% and mobile Lighthouse performance rose from 66 to 90.

## Challenges

Since the end of 2023, it was becoming clear to Evil Martians that Gastby was winding down and could not be the future of their corporate website and blog infrastructure. As the site grew to 1000+ built HTML pages, maintenance costs and code fragility were accelerating over time:

- **17 Gatsby plugins** in `package.json` alongside the framework itself, and **4 dependencies** that needed hand-written patches to behave.
- **A GraphQL data layer** sitting in front of a static site, with components and pages pulling their data through Gatsby-specific hooks.
- **Dependency advisories accumulating** with no upstream fix available, on a tree nobody was going to update.
- A **shrinking pool of Evil Martians with specialized Gatsby knowledge** who could safely touch the code.

Evil Martians needed to migrate to a modern framework to reduce technical debt and keep the site maintainable. But they also needed to do it with as little downtime as possible.

## Requirements

The Evil Martians team was looking for a way to make the migration manageable. They identified three non-negotiables:

- Whatever replaced Gatsby had to **accept existing React components**.
- **The GraphQL layer had to be replaced with something proportionate.** The replacement had to cover pages, components and a custom content pipeline without becoming its own migration.
- The new framework had to be **built alongside the old one in the same repo**. This would allow them to migrate as time and resources allowed, swapping new routes for old ones as they became available.

Fortunately, Astro checked all three boxes.

## Solution and Implementation

Astro's framework-agnostic, Island architecture and strong plugin ecosystem made the migration from Gatsby straightforward. Astro's first-party React integration meant that the existing component library ported over without any changes.

Astro's content collections replaced the GraphQL layer, and the team didn't have to change the content pipeline at all. The existing LiquidJS and JSX transformers continued to run, just behind collections instead of resolvers.

Astro's routing system allowed the migration to progress incrementally, with both frameworks built from the same project repository simultaneously. Astro went up alongside Gatsby, one route group at a time, while Gatsby kept serving production. Nothing went live until the whole site was ready, so the zero-risk migration could progress at its own pace, and even be paused at any time without affecting production.

## Results

Evil Martians was facing an aging framework, a GraphQL layer that was overkill for a static site, and a shrinking pool of engineers to maintain it.

The migration to Astro allowed the team to ship the homepage as a set of islands, first as full-pages, then with each section hydrating independently. This change alone reduced the amount of JavaScript shipped on load by 61%. 

Islands also made it obvious where the weight had been. They discovered that the heaviest element on the homepage was the site search modal, which had previously loaded on every route, whether opened or not. Deferring it to first open as an island took 437 KB off load across the site.

Deleting the GraphQL layer also deleted its expensive prefetch behavior. Gatsby pulled 13.6 MB of query results for links nobody had clicked yet, more than six times the weight of the page itself. The Astro version of the site waits for a hover before fetching any data.

Additionally, Evil Martians improved performance and security by reducing dependencies. 17 Gatsby plugins and 4 patched dependencies are now gone. `package.json` is down from 108 to 86 direct dependencies.

### Performance Gains

The migration to Astro was a clear success. The team was able to migrate the entire site in just eight days, without rewriting a single React component. The homepage went from 2.1 MB to 1.8 MB, and after fully converting to Island architecture, it's now 1.1 MB. Homepage JavaScript at load fell 61%, and mobile Lighthouse performance rose from 66 to 90.
